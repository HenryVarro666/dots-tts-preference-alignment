# 00 · 总览与步骤详解（每一步：做什么 / 怎么做 / 为什么 / 对实验意义）

> 读这一篇就能理解「为什么管线长这样」。每步都给四要素 + 输入输出 + 可能的失败信号。
> 配套：方法数学见 [`01-METHOD.md`](01-METHOD.md)，关键抉择见 [`02-DECISIONS.md`](02-DECISIONS.md)，跑序见 [`03-REPRODUCE.md`](03-REPRODUCE.md)，风险见 [`04-RISKS.md`](04-RISKS.md)。

## 一句话总览
在 dots.tts（连续-latent AR TTS）上，用**模型自己生成 + 自动多目标打分**的偏好数据做对齐/自训练，**实测得到一份警示性负面结果**：向 automatic-reward 选出的自生成 **off-manifold winner** self-train（SFT/DPO 均然）会退化模型、随拉力单调加剧，唯 `open_soar`（训向真实 on-manifold 目标）改善；机理是 **FM 似然与 perceptual reward 内在反相关**。本管线既产出这套裁决（第一轮 Table 1），也承载隔离/建设性/泛化的第二轮诊断（X1–X13，见 [`09-第二轮实验程序.md`](09-第二轮实验程序.md)）。

整条管线（▸ 标第二轮新增脚本/新臂）：
```
①data → ②candidates → ③reward → ④pairs → ⑤alignment → ⑥inference(离线+流式) → ⑦eval → ⑧ablation → ⑨results
  │         │▸--fixed-setting(X5)        │▸extract_{losers,random}(X4)  │▸probe_analysis(intrinsic)        │▸diagnose_eval(X2/X3)   │▸失败率入主表
  │▸多语种   │                            │▸filter_pairs_by_likelihood   │▸train_reward_weighted(X6b/X7)    │▸run_emergent_tts(X9)
  │ (X11)    │                            │  (on-manifold,X6a)           │▸sft_{losers,random,groundtruth}(X4)
  │          │                            │                              │▸dpo_onmanifold(X6a) reward_weighted{,_weronly}(X6b/X7)
  │          │                            │                              │▸probe_fm_reward_voxcpm(X10 跨架构)
  └────────────────────────────────────────────────────────────────────────────────────────────────→ (Phase B：远期 future work，未执行)
```
> run_matrix.py 的 `TREATMENTS` 已含全部新臂（base + 4 第一轮臂 + `sft_losers/sft_random/sft_groundtruth` + `dpo_onmanifold` + `reward_weighted{,_weronly}`）；所有 JSONL 契约 schema 不变。

## ① data — 构造 prompt 清单
- **做什么**：把 VCTK/AISHELL-3/LJSpeech 统一成 `PromptRow{fid,text,prompt_audio,prompt_text,lang}`，切 train/eval。
- **怎么做**：每语料一个 adapter（`data/prepare_prompts.py`）；按 `fid` 哈希切分。
- **为什么**：下游不该关心数据来自哪——这是「数据源↔算法」解耦层；哈希切分保证**无泄漏、可复现**。
- **对实验意义**：训练/评测不重叠是结论可信的底线。
- **输入/输出**：原始语料 → `data/prompts/{corpus}_{train,eval}.jsonl`。
- **失败信号**：某语料 0 行 → 路径/转写文件格式不对（看脚本告警）。

## ② candidates — 候选生成
- **做什么**：对每个 prompt 用 dots.tts 采 K 个**有差异**候选。
- **怎么做**：`candidates/generate_candidates.py` 复用 `DotsTtsRuntime.generate`；**因无 seed 参数**，多样性靠超参网格 + 逐候选 `seed_everything`。
- **▸第二轮 X5（settings-matched 复探针）**：`--fixed-setting` 固定 guidance×num_steps×speaker_scale，只靠 RNG 取差异——复证「FM 似然 vs reward 反相关」在固定生成设置下**仍存活**（排除 grid 副产品，呼应偏相关 −0.392 的 intrinsic 裁决）。
- **为什么**：DPO 需要「同条件下有高低差」的候选池；没差异就没偏好信号。**但多样池的 best-vs-worst winner 偏 off-manifold**（高-guidance 清晰但不典型）——这正是退化的毒源。
- **对实验意义**：候选差异度决定偏好信号质量；候选的 **on/off-manifold 位置**决定对齐是改善还是退化。
- **输入/输出**：`prompts/*_train.jsonl` → `candidates/out/{fid}/cand_k.wav` + `candidates_index.jsonl`。
- **失败信号**：③阶段奖励方差极小 → 回这里加大网格（见 04-RISKS 风险①）。

## ③ reward — 多目标打分
- **做什么**：每候选打 WER↓/SIM↑/UTMOS↑，z-norm 聚合成单一奖励 R。
- **怎么做**：`score_wer/sim/utmos.py`（复用 seed-tts-eval + speechmos）→ `aggregate_reward.py`。
- **为什么**：奖励的**组成**就是实验操纵变量（多目标 vs 仅 WER）；按候选池 z-norm 才能跨量纲可比。
- **对实验意义**：多目标 → RQ1；仅 WER → RQ3 的 reward-hacking 臂。
- **输入/输出**：`candidates_index.jsonl` → `reward/out/rewards.jsonl`。
- **失败信号**：聚合时打印的「候选池平均奖励方差」太小 → 偏好信号弱。

## ④ pairs — 构造偏好对
- **做什么**：按策略(best_worst/top2_bottom2/threshold)为每 prompt 生成 (win,lose) 对。
- **▸第二轮 X4（SFT-target 抽取）**：`extract_winners/losers/random.py` 抽出 best=最 off-manifold / worst / 随机 / （配 `sft_groundtruth` 的真实录音=on-manifold）四种 SFT target——隔离「off-manifold 目标退化」vs「小数据 SFT 本身不稳」。
- **▸第二轮 X6a（on-manifold 过滤）**：`filter_pairs_by_likelihood.py` 只保留 likelihood 高（on-manifold）的 winner 重建 pair，喂 `dpo_onmanifold` 救回 DPO-FM。
- **为什么**：win/lose **共享同一 text+prompt**，只差生成音频 → DPO 似然比纯粹反映「该偏向谁」。
- **对实验意义**：配对策略是消融维度（质量 vs 数量）；winner 的 on/off-manifold 位置是退化/改善的开关。
- **输入/输出**：`rewards.jsonl`(+candidates) → `pairs/out/pairs_{strategy}.jsonl`、`sft_{winners,losers,random}.jsonl`、`pairs_onmanifold.jsonl`。

## ⑤ alignment — 偏好对齐 / 诊断（**核心**）
- **做什么**：在 dots.tts-base 上做 DPO / SFT / open-SOAR，产出各 treatment ckpt；并跑机理探针。
- **怎么做**：`losses_dpo.py`(Diffusion-DPO over FM loss) + `train_dots_tts_dpo.py`(策略+冻结 ref+配对前向)；`train_sft.py`、`train_open_soar.py`。
- **▸第二轮**：`train_reward_weighted.py`（X6b/X7：朝 winner 做 reward 加权回归、**不**做 win/lose 的 `L_FM` 对比，配 `data_pairs.build_weighted_dataloader`——在非错配框架内干净复现 reward-hacking）；`sft_{losers,random,groundtruth}.yaml`（X4）；`dpo_onmanifold.yaml`（X6a）。
- **▸机理探针**：`probe_analysis.py`（偏相关 −0.392 → intrinsic 裁决、per-component、杠杆、双系数 CI）；`probe_fm_reward.py` / `probe_fm_reward_voxcpm.py`（X10 跨架构复证 + `voxcpm_preprocess.py`）。
- **为什么**：连续-AR 没有离散 token 的 log-prob → 用 **FM velocity 损失当 NLL 代理**（详见 01-METHOD）。**实测：`L_FM` 是有效似然代理（open_soar 同损失训满分为证）；崩坏不在 `L_FM`，在 preference-likelihood 对齐（off-manifold winner）。**
- **对实验意义**：产出所有 treatment 与机理裁决；这是项目从「配方」转向「诊断」的落点。
- **命门**：policy/ref×win/lose 四前向**共享同一 (x0,t)**（见 04-RISKS 风险②）。
- **输入/输出**：`pairs/*.jsonl` + base → `alignment/out/{treatment}/`；probe → `alignment/out/probe_per_pair.csv`。

## ⑥ inference — 离线 + 1T1A 流式合成
- **做什么**：用对齐 ckpt 把评测集合成 wav，**两种模式**。
- **怎么做**：`batch_synthesize.py`(离线) / `batch_synthesize_streaming.py`(1T1A，采集首包延迟)。
- **为什么**：评测须「同集同设置只换权重」；流式须走真实流式路径重测。
- **对实验意义**：离线→RQ1/RQ3；流式→RQ2。
- **注意**：流式克隆**仅 x-vector**（dots.tts 流式拒 prompt_text）。

## ⑦ eval — 评测 / 崩坏归因
- **做什么**：WER/SIM(score_synth) + UTMOS + EmergentTTS + 流式指标(首包/RTF/边界不连续度)。
- **▸第二轮 X2/X3**：`eval/diagnose_eval.py`（纯 CPU、秒级）双诊断——(a) 失败是否**聚集**（LJ002 块 / 长文本组）、(b) 25% 崩坏是 **optimization divergence 还是 graded**（读训练曲线 fm_w/reward_margin 末段 + probe_per_pair 交叉表）。**X9**：`run_emergent_tts.py` 实装（外部 LLM-judge API〔需核实〕）。
- **为什么**：所有 RQ 的证据在此产生；UTMOS/EmergentTTS 是检测退化的探针；diagnose_eval 诊断「25% 是生成时子集崩（graded-vs-divergence 证据不一、暂不定论）+ 失败聚集须诚实归因（评测集本身 89% 为 LJ002）」这两条 caveat。
- **对实验意义**：直接喂给结果表与 caveat。
- **纪律**：统一 ASR/speaker-encoder/子集；LLM-judge 胜率标「非绝对分」；**无人类听测前不称 perceptual/naturalness 退化**。

## ⑧ ablation — 实验矩阵
- **做什么**：跑 treatments × NFE × 模式，写**可溯源账本** `ledger.jsonl`。
- **为什么**：防「这个数字哪个设置跑的」之乱；每数绑定 (config,ckpt,NFE,模式,产物)。

## ⑨ results — 汇总出表/图
- **做什么**：`aggregate_results.py` 出主表/流式表/reward-hacking 表；`plots.py` 出图。
- **▸失败率入主表**：从每个 run 的 `_synthesis_report.json` 读 `failure_rate`，**与 WER 并列**写主表（如 `25.0% (25/100)`），否则低估崩坏。
- **对实验意义**：主表→RQ1 单调崩坏序、probe→RQ2 intrinsic 机理、reward_weighted_weronly→RQ3 干净复现，直接进论文（见 `docs/08`）。

## 全流程数据契约（一图记牢字段）
```
PromptRow   {fid,text,prompt_audio,prompt_text,lang}
  → CandidateRow {…,k,audio,num_steps,guidance_scale,speaker_scale,seed}
    → RewardRow  {…,k,audio,wer,sim,utmos,reward}
      → PairRow  {fid,text,prompt_*,win_audio,lose_audio,reward_win,reward_lose}

```
字段定义的单一事实源 = `common.py`。
